## 🚀 เปิดใช้งานบน GitHub Pages

**วิธีที่ 1 — ใช้ GitHub Actions (มีไฟล์ `.github/workflows/pages.yml` ให้แล้ว)**

1. เมิร์จโค้ดเข้าแบรนช์ `main`
2. ไปที่ **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
3. รอ workflow รันเสร็จ แล้วเปิด `https://<ชื่อผู้ใช้>.github.io/khaohom-random/`

**วิธีที่ 2 — เสิร์ฟจากแบรนช์ตรง ๆ**

1. **Settings → Pages → Source** เลือก **Deploy from a branch**
2. เลือกแบรนช์ที่ต้องการ และโฟลเดอร์ `/ (root)` แล้วกด Save

ทุก path ในโปรเจ็กต์เป็นแบบ relative (`assets/...`, `./index.html`) จึงทำงานได้ทั้งบน root domain และบน subpath ของ GitHub Pages
ไฟล์ `.nojekyll` ใส่ไว้กัน Jekyll ยุ่งกับไฟล์ในโปรเจ็กต์

### ตั้งเกณฑ์ตรวจเอง

เลือก **กำหนดเอง** ในหัวข้อการตรวจลายมือ แล้วเลื่อนตั้งได้สองค่า

- **⭐⭐⭐ ถูกต้อง** เมื่อเหมือนตั้งแต่กี่ % (40–100)
- **⭐⭐ ใกล้เคียง** เมื่อเหมือนตั้งแต่กี่ % (20–100)

ตัวเลขคือ % เดียวกับที่โชว์ในกล่องผลตรวจ ปรับแล้วกดตรวจซ้ำได้ทันที และระบบกันไม่ให้เกณฑ์ใกล้เคียงสูงกว่าเกณฑ์ถูกต้อง

## ✅ ระบบตรวจลายมือทำงานอย่างไร

`assets/js/checker.js` เทียบ **รูปร่าง** ที่เด็กเขียนกับตัวอย่างที่ถูกต้อง โดยประมวลผลในเครื่องทั้งหมด ไม่ส่งข้อมูลออกไปไหน ไม่ต้องใช้ API key และยังทำงานตอนออฟไลน์

1. แปลงทั้งลายมือและตัวอย่างเป็นแผนที่ความหนาแน่น 40×40 ช่อง โดยย่อ-ขยายให้พอดีกรอบและจัดกึ่งกลาง → เด็กเขียนใหญ่ เล็ก หรือเยื้องตรงไหนก็ไม่ถูกหักคะแนน
2. เบลอเล็กน้อย → เส้นเบี้ยวไปนิดหน่อยยังผ่าน
3. หารด้วยผลรวม → ปากกาหนาหรือบางไม่มีผลต่อคะแนน
4. คิดคะแนนจาก histogram intersection ผสม soft IoU แล้วตัดสินเป็น 3 ระดับ

**ผลทดสอบกับลายมือจำลอง** (28 ตัวอักษร/คำ แต่ละแบบบิดเส้นเป็นคลื่นแบบสุ่ม)

| ลักษณะการเขียน | คะแนนที่ได้ (ต่ำสุด–สูงสุด) |
|---|---|
| เขียนถูก เบี้ยวเล็กน้อย | 0.60 – 0.84 |
| เขียนถูก เบี้ยวมาก | 0.54 – 0.76 |
| เขียนถูก เบี้ยวหนักมาก | 0.46 – 0.67 |
| เขียนผิดตัว | 0.27 – 0.73 |
| เขียนมั่ว | 0.28 – 0.49 |
| ขีดเส้นเดียว | 0.10 – 0.23 |

เกณฑ์ตัดสิน (ปรับได้ในหน้าตั้งค่า) — ค่าเริ่มต้นคือ **ผ่อนปรน** เพราะออกแบบมาสำหรับเด็ก 5 ขวบ

| ระดับ | ⭐⭐⭐ ถูกต้อง | ⭐⭐ ใกล้เคียง |
|---|---|---|
| ผ่อนปรน | ≥ 0.58 | ≥ 0.45 |
| ปกติ | ≥ 0.65 | ≥ 0.52 |
| เข้มงวด | ≥ 0.72 | ≥ 0.60 |

**ข้อจำกัดที่ควรรู้**

- ตรวจเฉพาะรูปร่างโดยรวม **ไม่ได้ตรวจลำดับเส้นหรือทิศทางการลาก**
- ตัวที่รูปร่างใกล้กันมาก (ค/ด, ต/ด, บ/ป) อาจตัดสินพลาดได้บ้าง
- ถ้าอยากให้เด็กเขียนเล่นสบาย ๆ โดยไม่ถูกตัดสิน ปิดสวิตช์ “ตรวจให้ว่าเขียนถูกไหม” ได้ในหน้าตั้งค่า แล้วปุ่มจะกลับไปเป็น “เขียนเสร็จแล้ว!” ที่ชมทุกครั้งเหมือนเดิม
- ถ้ารู้สึกว่าตรวจง่ายหรือยากเกินไป ปรับเกณฑ์เองได้ที่ **กำหนดเอง**

## 🔢 เลขเวอร์ชัน

เลขเวอร์ชันแสดงอยู่ท้ายหน้าตั้งค่า เช่น `เวอร์ชัน 1.0.12` พร้อมรหัสคอมมิตและวันที่

เลข build นับจาก **จำนวนคอมมิตใน git** (`git rev-list --count HEAD`) จึงเพิ่มขึ้นเองทุกครั้งที่อัปเดต
ไม่ต้องแก้ด้วยมือ — ตอน deploy ขึ้น Pages workflow จะรัน `tools/bump-version.sh` ซึ่ง

1. เขียนไฟล์ `assets/js/version.js` ใหม่
2. ตั้งชื่อแคชของ Service Worker ให้ตรงกับเลข build (`khaohom-writing-b12`)

ข้อ 2 ทำให้ **iPad ได้ไฟล์ใหม่เสมอเมื่อมีการอัปเดต** ไม่ต้องมาไล่แก้เลขแคชเอง และแอปจะขึ้นข้อความบอกเมื่อโหลดเวอร์ชันใหม่เรียบร้อยแล้ว

ถ้า deploy แบบ **Deploy from a branch** (ไม่ผ่าน Actions) ให้รันสคริปต์นี้เองก่อน push

```bash
bash tools/bump-version.sh
```

การตั้งค่าทั้งหมด (หมวด ระดับ สีปากกา คะแนน) ถูกเก็บใน `localStorage` ของเครื่องนั้น ๆ
